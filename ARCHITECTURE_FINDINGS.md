# Architecture Review Findings

Full-codebase architecture audit (2026-07-18). Distinct from `CODE_REVIEW_FINDINGS.md` (line-level bugs, all fixed): these are structural/design problems. Checkboxes track future remediation work.

Recurring failure pattern across the codebase: **knowledge duplicated across hand-synchronized places with nothing enforcing agreement**, plus **advertised contracts the code doesn't implement**. The line-level code is careful; the seams between subsystems are where the debt lives.

## High severity

- [x] 1. **Schema has no single source of truth — drift has already happened.** *(Done 2026-08-01, by enforcement rather than by the `FieldSpec` refactor: five schema-consistency tests in `src/config/tests.rs` iterate every plugin and assert known-fields ⊆ type table, no dead type arms, checksum ⊆ known, descriptions ⊆ known. They found more drift than the audit listed — 19 dead arms (incl. `markdownlint.local_repo`/`npm_stamp`, not just the 8 named) and ~100 fields with no type validation at all. All fixed: `command`/`output_dir`/`formats` moved to the generic arm, ~40 processor-specific entries added (each verified against its struct declaration), `FieldType` gained `Table`/`Array`. The tests immediately caught a wrong type I introduced (`tags.sorted_tags` as StringArray), which is the point. **The `FieldSpec` consolidation itself is still worth doing** — the "no dead arms" check is probabilistic because `expected_field_type` is a match, not data; turning it into data makes that check total. Left as follow-up.)* One config field's schema lives in 5–8 hand-synced places (struct field, serde default fn, `Default` impl, `known_fields()`, `field_descriptions()`, `checksum_fields()`, `expected_field_type` arm in `src/config/mod.rs:1205`, docs page). - [x] 3. **Cache-key composition is decentralized, with correctness holes behind it.** *(Done 2026-08-01: new `src/cache_key.rs` owns composition. The opaque `Product.config_hash: Option<String>` — spliced by four contributors using three different separator conventions — is replaced by `CacheKey`, an ordered list of named `(Component, value)` pairs (`Config`/`Analyzer`/`ToolVersion`/`Variant`) folded into the digest by one function.
